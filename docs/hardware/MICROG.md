# microG in the KYF37 ROM

microG ("free" Google Play Services replacement) is part of every build from v14 on. Source reference:
<https://github.com/microg/GmsCore/wiki/Installation> (Android 7+ needs signature spoofing in the framework **or** GmsCore as a
privileged system app; we do both).

## What is installed

| Package | App | Version | Location | Source / SHA-256 prefix |
|---|---|---|---|---|
| `com.google.android.gms` | microG Services (GmsCore) | 0.3.17.252432 | `/system/priv-app/GmsCore` | microg.org/fdroid/repo, `e5e6cba078bdec81…` |
| `com.android.vending` | microG Companion (FakeStore) | 0.3.17.40226 | `/system/priv-app/FakeStore` | `9b8616011cc8f026…` |
| `com.google.android.gsf` | GSF proxy (legacy C2DM) | v0.1.0 | `/system/priv-app/GsfProxy` | `86891b174301f06a…` |

All three were downloaded from microG's official F-Droid repository and their SHA-256 matched the repository index
(`https://microg.org/fdroid/repo/index-v1.json`, repo fingerprint `9BD06727E62796C0130EB6DAB39B73157451582CBD138E86C468ACC395D14165`).
The original APKs are kept in WSL `~/microg/` and in the source tree at `packages/apps/MicroG/` (re-signed? **No** — PRESIGNED, untouched).

## Framework changes (signature spoofing)

Patch: `android_frameworks_base-Q.patch` from `lineageos4microg/docker-lineage-cicd`, applied to `frameworks/base`:
* new permission `android.permission.FAKE_PACKAGE_SIGNATURE` (dangerous, hidden);
* `PackageManagerService.mayFakeSignature()` returns the `fake-signature` metadata of an app that holds the permission;
* `com.google.android.gms` added to `config_locationProviderPackageNames` so GmsCore's fused/network location works.

## Permission files (generated by `device-inspection/install-microg.py`)

* `device/kyocera/kyf37/permissions/privapp-permissions-microg.xml` — every `signature|privileged` permission the three APKs request
  (generated from their manifests against the permission definitions found in the source tree). Android 10 **refuses to boot**
  (system_server crash) if a priv-app requests a privileged permission that is not allow-listed — if a microG update adds permissions,
  regenerate with the script.
* `default-permissions-microg.xml` — pre-grants `FAKE_PACKAGE_SIGNATURE`, location, phone state, accounts and storage to GmsCore
  (the spoofing permission is *dangerous*, so it must be granted at install time, otherwise apps do not see Google's signature).

## Updating microG

1. Look up the new version in the repo index; download the APK; verify its SHA-256 against the index.
2. Put it in `~/microg/`, adjust the file names in `install-microg.py` (`APKS` list) and run the script in WSL (idempotent).
3. Rebuild and verify first boot (watch for `Signature|privileged permissions not in privapp-permissions whitelist`).

## First use on the phone

1. Open **microG Settings** (Settings → System/“microG Settings”, or the launcher entry) → *Self-Check*: all items should be ticked
   (signature spoofing, Google device registration optional).
2. Enable *Google device registration* and *Cloud Messaging* only if you want Google sign-in / push; location back ends
   (Mozilla/Nominatim) are configured in the UnifiedNlp settings.
3. Disable battery optimisation for microG Services (Android Settings → Apps → Special access).
4. Wi-Fi is required for registration; the phone's Wi-Fi is being worked on (see `RADIO.md`).

## Aurora Store (preinstalled from v15)

`com.aurora.store` 4.8.4 (owner-supplied APK, sha256 `8a1ed9aa09631290da91cb793e0517b0f20dc70239ac94ae6682cd94f91a4bad`) is preinstalled as a normal
system app with its **original signature** (so it can update itself). Wired by `device-inspection/install-aurora-store.py`
(`packages/apps/AuroraStore`). It works with microG for Google login or anonymously. On this ROM installs go through the normal
package installer (confirmation dialog). Keep the APK in `~/microg/AuroraStore.apk` (and Downloads) when rebuilding from scratch.
